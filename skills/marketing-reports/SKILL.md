# Маркетинговый дашборд по сделкам Б24

## Цель

Дашборд для показа Партнёру: сколько заявок получают, какая конверсия, конверсия по
причинам отказов, сколько успешных сделок за период и в сравнении с прошлыми
периодами. Дашборд доступен по публичной ссылке в браузере; из дашборда всегда
собирается PDF — его отправляю Партнёру (публичная ссылка на HTML — резервный вариант).

## Входные данные

- Выгрузки из Б24 называются `Сделки из Б24_дд.мм.гггг.csv` (дата выгрузки) и кладутся
  в папку `data`. Кодировка — cp1251 (скрипт определяет её сам, конвертировать файл не нужно).
- Периоды привязываются к дате последних данных в выгрузке (якорь), а не к дате сборки —
  это считается в скрипте автоматически.
- Выводы и рекомендации генерируются скриптом автоматически по цифрам каждой выгрузки —
  дописывать их вручную не нужно.

## Сборка (по новому файлу выгрузки)

1. Статистика: `node scripts/compute_deals_stats.js "data/Сделки из Б24_дд.мм.гггг.csv"`
   (скрипт читает cp1251/UTF-8 автоматически и пишет `tmp/deals/stats.json`).
2. Дашборд: `node scripts/build_dashboard.js` — создаёт
   `reports/dashboard-marketing_дд.мм.гггг.html` (дата в имени — дата сборки из stats.json).
3. PDF через headless Edge (обязательно `--user-data-dir` и абсолютные пути):

   ```
   "/c/Program Files (x86)/Microsoft/Edge/Application/msedge.exe" --headless --disable-gpu \
     --user-data-dir="$TEMP/edge-quickpdf" --no-pdf-header-footer \
     --print-to-pdf="C:\...\marketing\reports\dashboard-marketing_дд.мм.гггг.pdf" \
     "file:///C:/Users/qwerty/Documents/Практикум Claude Code/marketing/reports/dashboard-marketing_дд.мм.гггг.html?print=1"
   ```

4. Открыть в браузере: `cmd //c start "" "<абсолютный путь к дашборду>"`.

## Ежедневная проверка

Каждый рабочий день утром в 09:00 проверять `data` на файл с сегодняшней датой:
есть — пересобрать дашборд и PDF и открыть дашборд в браузере; нет — коротко сообщить об этом.

## Состав метрик

1. Заявки за день / текущую неделю / текущий месяц / последние 30 дней — в разрезе
   каналов (поле «Источник») и ответственных. В верхнем KPI-ряду рядом с заявками
   в штуках — заявки в суммах (сумма по всем заявкам за период).
2. Конверсия в успех и в провал с расшифровкой по причинам отказа (те же периоды) —
   в целом, по ответственным, по источникам.
3. Скорость обработки новых сделок (перевод на стадию «Первый контакт») — в целом
   и по ответственным.
4. Успешные сделки за день / неделю / месяц / последние 30 дней — количество и сумма.
   Всего, по ответственным, по источникам.
5. Сравнение успешных сделок (количество и сумма): текущая неделя vs прошлая,
   текущий месяц vs прошлый, последние 30 дней vs 31–60 дней назад. Всего,
   по ответственным, по источникам.
6. Тренды по конверсии в успешные сделки — в разрезе каналов поступления и
   ответственных (в штуках и суммах).
7. Выводы и рекомендации — какие каналы привлечения лидов нужно усилить.

## Замечания по среде

- Python в системе нет, только Node.js — всё считается нативно в Node.
- Кодировка консоли: JSON-вывод скриптов в консоли может выглядеть «кашей» —
  это только отображение, в `tmp/deals/stats.json` и дашборде русский текст корректен.
- Файлы не удалять и не переименовывать без явного разрешения.
