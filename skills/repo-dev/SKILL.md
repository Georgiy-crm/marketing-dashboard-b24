# Работа с репозиторием маркетингового дашборда

## Цель

Скилл помогает Claude Code работать с проектом как с кодовой базой: понимать, что
где лежит, запускать и проверять сервис, вносить изменения безопасно и публиковать
их в GitHub, не вынося данные клиентов.

## Структура

- `scripts/compute_deals_stats.js` — CSV → статистика: читает выгрузку
  (автоопределение cp1251/UTF-8, разделитель «;»), классифицирует сделки
  (УСПЕХ / в работе / провал), считает агрегаты; пишет `tmp/deals/stats.json`.
- `scripts/build_dashboard.js` — `stats.json` → HTML-дашборд
  `reports/dashboard-marketing_дд.мм.гггг.html` (дата — якорь из stats.json).
- `scripts/pdf_render.ps1` — PDF из готового HTML через headless Edge.
- `scripts/gen_prev_period.js`, `scripts/patch_build_v2.js` — вспомогательные
  (генерация прошлых периодов, патчи сборки).
- `skills/marketing-reports/SKILL.md` — навык ежедневной сборки дашборда (рутина).
- `skills/repo-dev/SKILL.md` — этот навык.
- `docs/` — описание проекта (`2026-11-16-marketing-dashboard-overview.md`).
- `README.md` — публичная витрина репозитория.

**Не публикуется** (локально есть, в git не попадает): `data/`, `reports/`, `tmp/`,
`exports/`, `.claude/`, `CLAUDE.md`, любые CSV/PNG, внутренние инструкции в `docs/`
(«Инструкция по выпуску виртуальной карт.md», «Инструкция по настройке1S-Backoffice.docx»).
Правила уже в `.gitignore` — новые файлы с данными класть только в эти папки либо
добавлять в `.gitignore`.

## Запуск (полный цикл на последней выгрузке)

```bash
node scripts/compute_deals_stats.js "data/Сделки из Б24_дд.мм.гггг.csv"   # -> tmp/deals/stats.json
node scripts/build_dashboard.js                                           # -> reports/dashboard-marketing_*.html
```

PDF — только по необходимости (headless Edge, обязательно `--user-data-dir` и
абсолютные пути; команда — в `skills/marketing-reports/SKILL.md`).

Открыть дашборд в браузере: `cmd //c start "" "<абсолютный путь к html>"`.

Ожидаемый результат: `tmp/deals/stats.json` создан, HTML создан без ошибок,
в консоли скриптов виден «каша» из русского текста — это нормально (кодировка
консоли), в файлах всё корректно.

## Внесение изменений

1. Правка только в `scripts/` или `skills/`/`docs/`/`README.md` — данные в
   `data/reports/tmp` руками не менять.
2. После правок JS — синтаксис: `node --check scripts/<файл>.js` для каждого
   изменённого файла.
3. Прогнать полный цикл запуска на последней выгрузке (см. выше) — правка
   считается сделанной, только если дашборд пересобрался без ошибок.
4. При изменении метрик/состава дашборда — обновить и состав метрик в
   `skills/marketing-reports/SKILL.md`, если он затронут.
5. Ничего не удалять и не переименовывать без явного разрешения, пакеты не
   устанавливать (проект без внешних зависимостей — держать его таким).

## Проверка ошибок

- `node --check` по каждому изменённому JS-файлу.
- Полный цикл сборки на свежей выгрузке — скрипты должны отработать молча.
- Если выгрузки нет в `data/` — проверить только синтаксис и так сообщить,
  сборку не имитировать.
